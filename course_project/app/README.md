# Навчальний магазин: готовий застосунок

AdonisJS 6 + Lucid 21 + AdminJS 7 + MySQL. Реалізовано код із [покрокового посібника](../instructions_nodejs.md): сім моделей, три міграції, CRUD довідників, вхід адміністратора, транзакційне створення замовлення та HTML/JSON-звіт.

## Запуск у цьому робочому каталозі

Потрібні Node.js 22 та запущений локальний MySQL. Перевірте `node --version` саме в каталозі застосунку; якщо користуєтеся nvm, виконайте `nvm use` (версія задана в `.nvmrc`). `.env` уже налаштований: база `course_project`, користувач `root`, порожній пароль, порт `3306`.

З кореня репозиторію:

```bash
cd course_project/app
npm ci
npm run db:migrate
npm run db:seed
npm run dev
```

Відкрийте <http://127.0.0.1:3333/admin>.

Для підготовленого локального `.env`:

- Email: `admin@example.test`
- Навчальний пароль: `CourseAdmin2026!`

Змінити пароль можна командою `npm run admin:password`, після чого потрібно перезапустити сервер. Пароль панелі не пов’язаний із порожнім паролем MySQL. `.env` не передається через Git; наведений навчальний пароль застосовується лише до підготовленого локального файла.

## Перший запуск після клонування

```bash
cd course_project/app
npm ci
npm run setup:env
npm run admin:password
```

`setup:env` створює `.env` із шаблону та генерує відсутній `APP_KEY`; наявні налаштування й ключ не замінює. `admin:password` запитує ваш пароль і записує його хеш. Перевірте `DB_*` та `ADMIN_EMAIL` у `.env`.

Якщо бази ще немає, виконайте в DBeaver або клієнті MySQL:

```sql
CREATE DATABASE IF NOT EXISTS course_project
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
```

Потім:

```bash
npm run db:migrate
npm run db:seed
npm run dev
```

Міграції додають лише ще не застосовані зміни. Seeder повторно використовує навчальні записи, але повертає їхні початкові значення ціни й залишку. Команди очищення бази для запуску не потрібні.

## Що перевірити в інтерфейсі

1. Після входу відкрийте товари: там є «Навчальний ноутбук», SKU `LAPTOP-001`, ціна `25000.00`.
2. Створіть замовлення для Олени Тестової, виберіть її адресу, цей товар і кількість `2`.
3. Перевірте позицію замовлення й дію `report` у ресурсі замовлень. Вартість — `50000.00`.
4. Відкрийте [HTML-звіт](http://127.0.0.1:3333/reports/orders?format=html) або [JSON-звіт](http://127.0.0.1:3333/reports/orders). Обидва потребують входу.

Замовлення створюється разом із позицією; довільне редагування та видалення замовлень і позицій у панелі вимкнені. Ціна копіюється з каталогу. Залишки автоматично не списуються, а реєстрація платежу не проводить банківську операцію та не змінює статус замовлення.

## Перевірки та відповідність посібнику

```bash
npm run typecheck
npm run lint
npm test
npm run build
```

Шість тестів перевіряють відхилення некоректних даних замовлення, безпечне формування HTML та серіалізацію полів моделей для AdminJS. Вони не змінюють дані БД; ручні сценарії з посібника перевіряють також SQL-обмеження й транзакції.

| Частина посібника                         | Готовий код                                                                  |
| ----------------------------------------- | ---------------------------------------------------------------------------- |
| Підключення до MySQL                      | `config/database.ts`, `start/env.ts`                                         |
| Початкова схема, опис товару, індекс дати | Три файли в `database/migrations/`                                           |
| Сім моделей                               | `app/models/`                                                                |
| Навчальний набір даних                    | `database/seeders/demo_seeder.ts`                                            |
| Адмінка та вхід                           | `config/adminjs.ts`, `app/admin/`                                            |
| Створення замовлення                      | `app/services/order_service.ts`                                              |
| Контролер і HTML-звіт                     | `app/controllers/reports_controller.ts`, `app/services/order_report_view.ts` |
| Маршрути                                  | `start/routes.ts`                                                            |

Відмінності конфігурації від навчальних команд: каталог називається `app`; база — `course_project`; для локального MySQL дозволений порожній `DB_PASSWORD`. Усі зміни схеми з додаткових розділів уже включені. База керується міграціями; SQL-скрипти основного практикуму сюди імпортувати не потрібно.

Для роботи використовуйте один hostname — `127.0.0.1`; сервер зупиняється через `Ctrl+C`. Якщо порт `3333` зайнятий, змініть `PORT` у `.env`. При помилці підключення перевірте, що MySQL запущено й `DB_*` відповідають вашій інсталяції. Збірка `build` не є командою запуску: для локальної демонстрації використовуйте `npm run dev`.
